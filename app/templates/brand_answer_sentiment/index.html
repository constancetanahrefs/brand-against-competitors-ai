Source. ahrefs_brand_radar.ai_responses_results, scoped to the selected report's brands/competitors, one call per platform + dataset, date=null so every dated snapshot is returned, paged 1,000 rows at a time. Rows are stored locally and deduped on a hash of (report, dataset, platform, snapshot date, prompt, answer).

      
Mention detection. Brand Radar returns an empty matched_brands on this endpoint, so mentions are detected here with a whole-word, case-insensitive regex over every alias of every brand in the report. A response with no alias hit is not mentioned — no LLM call needed.

      
Sentiment. For mentioned responses, up to 2 excerpts of ±340 characters around the mentions are sent in batches to gemini-3-flash with a fixed rubric: positive = recommended/praised with no material criticism; neutral = named or described without evaluation; mixed = praise and criticism together or recommended-with-caveats; negative = criticism dominates. One verdict per response per subject brand, stored permanently — re-runs and new months never re-pay for an old response.

      
Criticism intensity. negative × 2 + mixed × 1, summed over all dated responses for that prompt under the current filters.

      
Search volume. The monthly search volume Brand Radar reports for the query behind the prompt; the maximum across that prompt's snapshots is shown.

      
Reading the answers. AI answers are markdown, so they're rendered as formatted text — headings, lists, tables, bold, links. Provider artifacts are cleaned first: empty citation markers like [](#cp0) (the cited URLs are listed separately under each answer) and backslash-escaped punctuation such as \$49 or 1\.. Answer HTML is sanitised before display because the text comes from a third party. In the single-response view, View raw markdown shows the untouched source.

      
Brand highlighting. Inside every answer, the subject brand is highlighted in amber, competitors from the same Brand Radar report in blue, and niche entries in purple. Matching uses the same whole-word alias rule as mention detection, longest alias first (so "Ahrefs Brand Radar" isn't split into "Ahrefs"), and only ever touches visible text — never a URL or link target. Hover a highlight to see which tracked brand it belongs to.

      
Prompt drill-down. Clicking any prompt row (criticism table, praise table or a trend mover) opens every dated response for that prompt, with its own filter bar: platform, sentiment, mentioned-vs-absent and sort. Those filters apply within the prompt and stack on top of the page-level scope; the counts beside each checkbox are for this prompt and stay fixed while you filter, so you can always see what else is in there. Leaving the platform boxes unticked falls back to whatever Report settings has selected.

      
Browse tab. One row per fetched answer, paged from the database (never all at once). It inherits the report / subject / platform / dataset / country / month choices from Report settings, then adds sentiment, mentioned-vs-absent, free-text and sort filters. Counts next to each sentiment checkbox are the facet totals under the other active filters. Rows fetched but not yet classified show as unjudged rather than being hidden, so the table total always equals what was actually pulled.

      
Everything on this page is computed from stored rows. Changing platform, country, month, sort or subject brand costs nothing. Only Fetch (Brand Radar pull) and Analyse (LLM verdicts) spend anything, and both are explicit buttons.
